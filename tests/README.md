# Tests

Grammar tests use [textmate-grammar-test](https://github.com/serkonda7/textmate-grammar-test),
which tokenizes a source file with this extension's grammars and records the scope assigned to every token.

```bash
npm ci
npm test                  # verify fixtures against committed snapshots
npm run test:snap:update  # regenerate snapshots after an intentional change
```

## How it works

Each fixture in `tests/fixtures/<language>/` has a committed `.snap` sidecar beside it. 
The first line is a generated header; after that, every source line is echoed with a leading `>`, 
followed by one `#` line per run of characters giving the scopes that run received:

```
# SYNTAX TEST "source.bnd" "autogenerated snapshot test"
>  EXPORT SYMBOL (interest>>>)
#^^ source.bnd
#  ^^^^^^ source.bnd keyword.other.bnd
#        ^ source.bnd
#         ^^^^^^ source.bnd support.function.bnd
#               ^^^^^^^^^^ source.bnd
#                         ^^^ source.bnd keyword.other.bnd
#                            ^^ source.bnd
```

Every run is listed, including unscoped ones. A row ending in just the root scope (`source.bnd`) means those characters received **no** highlighting - above,
that is the whitespace, the parenthesis, and `interest`. The signal is in the rows carrying a second scope. A run that you expect to be highlighted but that
shows only the root scope is a grammar gap.

`npm test` re-tokenizes each fixture and fails if the result differs from its
snapshot, so a grammar change that moves any token shows up as a `.snap` diff.

To check a single file while iterating:

```bash
npx textmate-grammar-snap "tests/fixtures/bnd/wildcards.bnd"
```

## Reviewing a change

**The `.snap` diff is the point.** It is the evidence that a grammar edit did what it claimed and nothing more:
- Grammar changed, snapshots unchanged - the edit had no effect.
- Snapshots changed in ways the PR does not explain - unintended side effect.
- A formatting-only change should produce **no** snapshot diff at all.

When a snapshot changes, the PR should say which tokens moved and why.

## Adding a fixture

1. Write the source under `tests/fixtures/<language>/`, one feature group per file, with a header comment recording the documentation source and the date it was retrieved.
2. Run `npm run test:snap:update` and read the generated `.snap`.
3. Commit the fixture and its snapshot together.

Fixtures are written from IBM documentation and are intended to be valid, compilable source. 
Where a fixture cannot compile - an exhaustive keyword list, or a deliberately malformed case - say so in its header.

If a fixture exposes a grammar bug, commit it first with the current (wrong) snapshot, then fix the grammar in a follow-up change. 
The second diff then shows exactly the correction.

## Documenting grammar rules

TextMate rules accept a `comment` key, which has no runtime cost. When working on a grammar, give every rule one:

```json
{
    "comment": "Wildcard characters in EXPORT SYMBOL, e.g. SYMBOL(interest>>>)",
    "name": "keyword.other.bnd",
    "match": "(<<<|>>>)"
}
```

Say what the rule matches in language terms, and record anything a future reader would otherwise have to re-derive from IBM documentation: 
undocumented behaviour, a scope name that looks wrong but is deliberate, or which source column a lookbehind is anchoring to.
